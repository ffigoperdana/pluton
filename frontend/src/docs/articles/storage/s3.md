# Menambahkan storage S3 untuk backup atau replika

Gunakan S3 untuk menyimpan repository pada object storage yang sesuai kebutuhan Anda. Siapkan terlebih dahulu bucket, endpoint, region, dan akun dengan akses terbatas. Satu konfigurasi yang tampil pada form tidak berarti seluruh vendor, kebijakan bucket, atau kelas penyimpanan sudah diuji.

S3 dapat menjadi primer pada alur filesystem yang dijalankan host Pluton. Untuk Managed Agent, primer tetap SFTP; S3 digunakan sebagai 0–2 replika opsional yang disalin server setelah verifikasi snapshot. Agent tidak menerima kredensial S3.

## Dukungan yang ada

Pilih **AWS S3** untuk konfigurasi AWS atau **S3 Compatible Storage** untuk endpoint kompatibel yang disetujui operator. Mode HCP dengan namespace yang sudah ada memiliki [panduan tersendiri](/docs/storage/hcp). Interoperabilitas HCP nyata belum diuji.

Pastikan provider mengizinkan operasi yang diperlukan oleh lifecycle yang akan digunakan, serta biaya request, transfer, dan pemulihannya dipahami. Jangan memilih kelas penyimpanan dengan pengambilan tertunda sebelum menilai dampaknya terhadap restore.

## Mengisi formulir

1. Buka **Storages → + New** dan isi **Storage Name***, misalnya `Object storage contoh`.
2. Pilih **Storage Type***: **AWS S3** atau **S3 Compatible Storage**.
3. Buka **Account Authentication** dan isi **Access Key ID**, **Secret Access Key**, **Bucket Name**, serta **Region** sesuai provider.
4. Untuk S3 compatible, isi **Endpoint** API yang benar, misalnya `https://objects.example.internal`. Untuk AWS, endpoint dapat mengikuti konfigurasi region.
5. Isi **Location Constraint** hanya sesuai kebutuhan provider. Tinjau **Advanced Options** bila diperlukan; jangan menyalakan akses publik atau menonaktifkan pemeriksaan keamanan untuk menghilangkan error.
6. Klik **Add Storage**, kemudian pilih storage itu pada plan yang sesuai.

## Local destination

Jika Anda sebenarnya ingin menyimpan pada disk yang terpasang ke host Pluton, gunakan [storage Local](/docs/storage/local). Path lokal mengacu pada filesystem yang dilihat proses server/container. Bucket S3 bukan folder lokal meskipun namanya mirip.

Pada pemilih tujuan S3, UI menampilkan awalan bucket bila tersedia. Jika bucket contoh adalah `example-backups` dan field subfolder diisi `app-01/primary`, tujuan lengkapnya menjadi `example-backups/app-01/primary`. Jangan mengulang bucket pada field subfolder yang sudah memiliki awalan.

Untuk replika Managed Agent, gunakan prefix khusus, misalnya `app-01/replica`, bukan root bucket. Prefix tidak boleh tumpang tindih dengan repository lain atau prefix managed yang dipertahankan. Ikuti [replikasi Managed Agent](/docs/replication/managed-agent).

## S3-compatible

Sesudah storage tersimpan, lakukan uji pada data sekali pakai. Untuk primer standar, jalankan backup, **Browse**, dan restore. Untuk replika managed, pastikan backup primer selesai, status replika berhasil, dan detailnya sesuai snapshot yang diharapkan. Restore langsung dari mirror managed belum didukung; status salinan bukan bukti uji pemulihan darinya.

Jika akses ditolak, periksa key, region, endpoint, scope bucket/prefix, serta waktu server. Jika TLS gagal, perbaiki trust atau hostname melalui operator. Hindari menaruh key pada URL atau membagikan raw request/log.

## Capacity

Pantau quota dan pemakaian fisik melalui provider, serta ruang cache/staging pada Pluton. **Snapshot Size** menunjukkan data logis, bukan ukuran fisik bucket. Jangan menetapkan object lifecycle yang menghapus blok repository hanya karena umur objeknya; snapshot yang masih dipertahankan dapat merujuk blok tersebut.

Baca [keamanan storage](/docs/storage/security) sebelum retensi atau penghapusan, dan [status serta retry replika](/docs/replication/status-retry) bila penyalinan gagal.
